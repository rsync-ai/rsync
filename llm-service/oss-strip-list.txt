# Paths (relative to llm-service/) that carry the connector-generation moat.
#
# SINGLE SOURCE OF TRUTH. Three consumers must agree with this file, and a guard
# test (tests/test_oss_image_boundary.py) fails the build if any of them drifts:
#
#   1. Dockerfile.community  — the published community image (llm-service-oss).
#                              Its COPY allowlist must cover EXACTLY the tracked
#                              files under src/ and prompts/ that are NOT listed here.
#   2. Dockerfile.oss        — the published connector-lifecycle image. A strict
#                              subset of (1); it may ship less, never more.
#   3. docs/internal/public-flip-runbook.md §2a — the paths deleted from the public
#                              source tree. Same list, so "moat-free image" and
#                              "moat-free repo" cannot diverge.
#
# Why a list and not "delete the whole tool_generator package": the connector
# DEPLOY runtime (deployment/) lives inside that package and is what the Go data
# plane calls on every self-heal / JIT build. It is moat-free by construction --
# deployment/routes.py's module docstring records that it must never import
# .orchestrator, ..config or any generation agent. Stripping it too would leave the
# community stack unable to start a connector at all.
#
# Every path here MUST exist on disk. The guard test asserts that, so a rename
# cannot silently turn a strip entry into a no-op that ships the moat.
