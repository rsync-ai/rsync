# Security
# Ceiling is not ours: presidio-anonymizer 2.2.364 -- the newest release --
# floors cryptography at 48.0.1 and caps it below 49, so anything from 49 up
# cannot resolve at all (verified against the package metadata on PyPI, not
# inferred). Stated explicitly as a pin so pip reports a chosen bound instead
# of a 20-line ResolutionImpossible dump. Raise it when presidio widens, not
# before. The floor patches the GHSA-537c-gmf6-5ccf class of issue; it used to
# be 42.0.0.
#
# Those bounds are written in prose deliberately. This comment previously
# spelled them in PEP 508 syntax, and #916 rewrote THE COMMENT instead of the
# pin below it -- flipping it to claim presidio *requires* 49, the opposite of
# the truth -- while the pin itself did not move.
#
# The reason given here for that was wrong, and it lasted one day. It said the
# pin was "correctly held by the ignore rule" in .github/dependabot.yml. It was
# not held by anything: that rule was scoped by `update-types`, a Dependabot
# requirement-range edit carries no update-type, so the rule matched nothing.
# #922 then proposed >=49.0.0,<50.0.0 directly onto the line below -- the pin,
# not the comment -- and would have shipped a requirements file that cannot
# resolve. The ignore entry is now bounded by `versions` instead, which needs no
# classification to match; the full account is in .github/dependabot.yml beside
# the rule. Keep version constraints out of the prose in this file anyway, but
# for the honest reason: a comment that looks like a requirement is noise a
# reader can misread, not a shield for the pin.
cryptography>=48.0.1,<49.0.0
