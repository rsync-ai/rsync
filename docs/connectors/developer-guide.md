# MCP Connector Developer Guide
## Creating AI-Compatible Data Connectors

> **Before you fix a hand-curated connector:** a fix to a hand-curated connector (`postgresql`, `mysql`, `shopify-admin-graphql`, `google-sheets`) MUST also be applied to its Jinja template and the affected connectors regenerated — otherwise every future AI-generated connector ships with the same bug.
>
> **Adding a new database to CDC** (not a general connector)? See [add-cdc-database.md](add-cdc-database.md) instead.
>
> **Adding a CDC _destination_** (warehouse / API / object store)? It must participate in exactly-once offset tracking — see [cdc-exactly-once-offsets.md](cdc-exactly-once-offsets.md) for the Tier A/B/C per-destination implementation guide (this replaces Redis dedup).

## Overview
All MCP connectors MUST follow a **generic interface** to enable AI agents to discover, understand, and interact with ANY data source uniformly.

## Quick Start

### 1. Generate a New Connector

Connectors are generated by the **tool-generator** service in `llm-service`, from an
OpenAPI/GraphQL spec or a database description — there is no scaffolding script to run
by hand. The service writes a complete connector into
`shared/mcp-connectors/<area>/<name>/versions/<version>/` and can then build and start
its container:

| Step | Endpoint | Self-hosted? |
|---|---|:--:|
| 1. Generate the connector source | `POST http://tool-generator:5010/v1/generate` | ❌ |
| 2. Build and start its container | `POST http://connector-deployer:5011/v1/deploy` | ✅ |

Neither port is published to the host — both services are internal to the compose
network, and both require the shared internal-service secret (`X-Internal-Secret`).
Call them from inside the network, or drive the same path from the UI's
"add a connector" flow, which is what it does.

> **Step 1 is not available in a self-hosted stack.** The connector *generation* package
> is stripped from the published images (`llm-service/oss-strip-list.txt`), and the
> container named `tool-generator` runs `python -m src.lifecycle.main` instead — which
> serves `/health`, `/version` and `/v1/deploy`, but **not** `/v1/generate`. Step 2 is
> deliberately kept, because the Go data plane calls it on every self-heal and
> just-in-time connector build.
>
> Self-hosted, add a connector by writing it by hand against the interface documented
> below, then deploying it with step 2. The rest of this guide applies unchanged — it
> describes the contract a connector must satisfy, however it was produced. Full
> boundary:
> [what you get when you self-host](../deployment/self-host-feature-boundary.md#connector-generation-what-exactly-is-missing).

**Categories.** The vocabulary is fixed by `CATEGORY_CONTRACTS` in
`llm-service/src/agents/tool_generator/contracts/registry.py`; the value you pick lands
in `metadata.json` as `category` and decides which contract the connector is held to.

| Category | Examples in this repo |
|---|---|
| `relational_db` | postgresql, mysql, oracle, sqlserver, clickhouse, redshift |
| `document_db` | mongodb |
| `wide_column_db` | — none yet |
| `data_warehouse` | snowflake, bigquery, databricks |
| `cloud_storage` | aws-s3, azure-blob, gcs |
| `api_saas` | stripe, github-rest, notion-rest, google-sheets, shopify-admin-graphql |

For object storage, the canonical config schema — file format, compression,
partition-by, source file→table mapping, INV-1 isolation — is in
[cloud-storage-config.md](cloud-storage-config.md).

`streaming` and `sample` also appear on disk (`debezium`, `kafka-mcp-sink`,
`sample-data`) but are internal or demo connectors and have no generator contract.

Generation writes, into `versions/<version>/`:

- `connector.py` — the connector itself
- `base_connector.py` — a vendored snapshot of the canonical base class
- `metadata.json` — what the product reads to decide what to offer
- `spec.json` — the source spec it was generated from
- `requirements.txt`, `Dockerfile` — so the directory builds standalone

and a `latest.json` at the connector root pointing at that version. Everything after
this point is editing `versions/<current_version>/connector.py`.

### 2. Implement Core Methods

Edit `connector.py` and implement:

#### ✅ **test_connection()** - REQUIRED
Test connectivity without reading data.

```python
def test_connection(self, params: Dict = None) -> Dict[str, Any]:
    config = params.get('config', params) if params else {}
    try:
        conn = self._get_connection(config)
        # Test query (e.g., SELECT 1, ping, etc.)
        conn.close()
        return {
            "success": True,
            "message": "Connection successful",
            "version": "1.0.0"  # Actual version
        }
    except Exception as e:
        return {"success": False, "error": str(e)}
```

#### ✅ **discover_schema()** - REQUIRED FOR AI
This is the MOST IMPORTANT method for AI agents!

```python
def discover_schema(self, params: Dict = None) -> Dict[str, Any]:
    """
    AI agents call this to understand your data source.
    Return tables/collections/buckets with their schemas.
    """
    config = params.get('config', params) if params else {}
    include_row_counts = params.get('include_row_counts', True)
    
    tables = []
    
    # For databases:
    for table_name in self._list_tables(config):
        columns = []
        for col in self._describe_table(config, table_name):
            columns.append({
                "name": col['name'],
                "type": col['type'],
                "nullable": col['nullable']
            })
        
        table_data = {
            "name": table_name,
            "columns": columns
        }
        
        if include_row_counts:
            table_data["row_count"] = self._count_rows(table_name)
        
        tables.append(table_data)
    
    return {
        "success": True,
        "tables": tables,
        "total_tables": len(tables)
    }
```

**Connector-Specific Examples:**

**Databases (MySQL, PostgreSQL):**
```python
# List tables
SELECT table_name FROM information_schema.tables 
WHERE table_schema = 'public'

# Describe table
SELECT column_name, data_type, is_nullable 
FROM information_schema.columns 
WHERE table_name = 'users'

# Row count
SELECT COUNT(*) FROM users
```

**Cloud Storage (S3, GCS):**
```python
# "Tables" = Buckets or prefixes
# "Columns" = Inferred from file schema
tables = [{
    "name": bucket_name,
    "columns": self._infer_schema_from_sample(bucket),
    "row_count": self._count_files(bucket)
}]
```

**APIs/SaaS (Salesforce, HubSpot):**
```python
# "Tables" = API endpoints
# "Columns" = API response fields
tables = [{
    "name": "contacts",
    "columns": [
        {"name": "id", "type": "string", "nullable": false},
        {"name": "email", "type": "string", "nullable": false},
        ...
    ]
}]
```

#### ✅ **validate_config()** - REQUIRED
Validate config without connecting.

```python
def validate_config(self, params: Dict = None) -> Dict[str, Any]:
    config = params.get('config', params) if params else {}
    errors = []
    warnings = []
    
    # Check required fields
    required = ['host', 'user', 'database']
    for field in required:
        if not config.get(field):
            errors.append(f"Missing required field: {field}")
    
    # Check optional fields
    if not config.get('password'):
        warnings.append("No password - connection may fail")
    
    return {
        "success": len(errors) == 0,
        "valid": len(errors) == 0,
        "errors": errors,
        "warnings": warnings
    }
```

#### ✅ **export()** - REQUIRED FOR SOURCES
Extract data for replication.

```python
def export(self, params: Dict) -> Dict[str, Any]:
    config = params.get('config', params)
    table = params.get('table')
    limit = params.get('limit', 10000)
    offset = params.get('offset', 0)
    
    conn = self._get_connection(config)
    cursor = conn.cursor()
    
    query = f"SELECT * FROM {table} LIMIT {limit} OFFSET {offset}"
    cursor.execute(query)
    
    columns = [desc[0] for desc in cursor.description]
    rows = cursor.fetchall()
    data = [dict(zip(columns, row)) for row in rows]
    
    return {
        "success": True,
        "data": data,
        "columns": columns,
        "row_count": len(data),
        "has_more": len(data) == limit
    }
```

#### ⚪ **import_data()** - OPTIONAL (for destinations)
Load data into destination.

```python
def import_data(self, params: Dict) -> Dict[str, Any]:
    config = params.get('config', params)
    table = params.get('table')
    data = params.get('data', [])
    
    conn = self._get_connection(config)
    cursor = conn.cursor()
    
    for row in data:
        columns = ', '.join(row.keys())
        placeholders = ', '.join(['%s'] * len(row))
        query = f"INSERT INTO {table} ({columns}) VALUES ({placeholders})"
        cursor.execute(query, list(row.values()))
    
    conn.commit()
    
    return {
        "success": True,
        "rows_inserted": len(data)
    }
```

### 5. Update Metadata

Edit `metadata.json`:
```json
{
  "name": "myconnector",
  "display_name": "My Connector",
  "version": "1.0.0",
  "category": "relational_db",
  "capabilities": {
    "max_batch_size": 10000,
    "supported_formats": ["csv", "json"],
    "supports_cdc": false
  },
  "operations": [
    {"name": "test_connection", "type": "core", "description": "Test connectivity"},
    {"name": "discover_schema", "type": "core", "description": "Discover tables and columns"},
    {"name": "validate_config", "type": "core", "description": "Validate configuration"},
    {"name": "export",          "type": "core", "description": "Read rows"},
    {"name": "import_data",     "type": "core", "description": "Write rows"}
  ],
  "configuration_schema": {
    "type": "object",
    "required": ["host", "user"],
    "properties": {
      "host": {"type": "string"},
      "user": {"type": "string"},
      "password": {"type": "string", "sensitive": true}
    }
  }
}
```

**`capabilities` is a map of feature flags; `operations` is the list of methods you
implement.** They are not interchangeable, and putting method names in `capabilities`
produces a connector that passes a shallow read but advertises no operations at all.
`discover_schema` must appear in `operations` — without it the planner has nothing to
work from.

#### Optional: `supported_versions` (database connectors)

Database connectors should advertise which engine versions rsync supports,
keyed by sync mode. This block is surfaced read-only in the connection-config
modal (`UnifiedConnectorModal`) so users know up front whether their server
version is compatible — especially for CDC, which has stricter minimums.

```json
"supported_versions": {
  "batch": "PostgreSQL 9.4 and later (12+ recommended)",
  "cdc": "PostgreSQL 10 and later — logical replication via Debezium pgoutput (requires wal_level=logical)"
}
```

Keys are sync modes (`batch`, `cdc`); values are human-readable version
strings shown verbatim in the UI. Omit a key if that mode is unsupported.

Plumbing: `metadata.json` → api-gateway `MCPConnector.SupportedVersions`
(`tools.go`) → frontend `MCPConnector.supported_versions`
(`lib/types/mcp-connector.ts`) → modal note. Edit it in
`versions/<current_version>/metadata.json` — the version named by
`latest.json.current_version`, which is the only copy that exists and the one the
Docker build context points at.

## AI Agent Interaction Flow

```
1. User selects data source in UI
2. Frontend calls: GET /api/v1/connections/{id}/metadata
3. API Gateway → Orchestrator → AI Agent
4. AI Agent calls: connector.discover_schema()
5. Connector returns: {tables: [...], columns: [...]}
6. AI Agent analyzes schema:
   - Identifies PII fields (email, ssn, etc.)
   - Suggests transformations (mask, encrypt)
   - Recommends tables to replicate
7. Frontend displays: Real tables, columns, row counts
8. User selects tables and creates pipeline
9. AI Agent orchestrates: export() → transform() → import()
```

## Best Practices

### ✅ DO:
1. **Always implement `discover_schema()`** - Critical for AI!
2. **Return consistent error format** - `{"success": false, "error": "msg"}`
3. **Use connection pooling** - For performance
4. **Handle pagination** - Support large datasets
5. **Log errors clearly** - Help debugging
6. **Test with real credentials** - Not just mocks
7. **Document config schema** - In metadata.json
8. **Inherit from BaseMCPConnector** - For consistency

### ❌ DON'T:
1. **Hardcode credentials** - Use config params
2. **Return different response formats** - Be consistent
3. **Ignore errors** - Always return error details
4. **Skip validation** - Implement validate_config()
5. **Assume database exists** - Handle missing DBs gracefully
6. **Return raw bytes** - Serialize to JSON-compatible types
7. **Block indefinitely** - Use timeouts
8. **Skip discover_schema()** - AI agents need it!

## Performance Optimization

### 🎯 Goal: `discover_schema` in < 2 seconds for 100+ tables

Schema discovery is the MOST CRITICAL operation for AI agents. Slow discovery = poor UX.

### ⚡ Optimization Checklist

#### 1. Use Metadata Catalogs (Not Data Scans)

✅ **Fast** (< 1 second for 100 tables):
```python
# MySQL: INFORMATION_SCHEMA
"SELECT TABLE_NAME, TABLE_ROWS FROM INFORMATION_SCHEMA.TABLES"

# PostgreSQL: pg_stat_user_tables  
"SELECT relname, n_live_tup FROM pg_stat_user_tables"

# MongoDB: estimated counts
collection.estimated_document_count()
```

❌ **Slow** (35+ seconds for 77 tables):
```python
for table in tables:
    # DON'T DO THIS - each takes 1-5 seconds!
    cursor.execute(f"SELECT COUNT(*) FROM {table}")
```

#### 2. Batch Queries (Not Per-Table Loops)

✅ **Fast** (1-2 queries total):
```python
# Get ALL columns for ALL tables in ONE query
cursor.execute("""
    SELECT table_name, column_name, data_type
    FROM information_schema.columns  
    WHERE table_schema = %s
""", (database,))

# Group columns by table in memory (fast!)
for col in cursor.fetchall():
    columns_by_table[col[0]].append({...})
```

❌ **Slow** (N queries for N tables):
```python
for table in tables:
    # Each query adds network latency!
    cursor.execute(f"DESCRIBE {table}")
```

#### 3. Set Reasonable Limits

```python
def discover_schema(self, params):
    # Prevent scanning 1000+ tables
    max_tables = params.get('max_tables', 100)
    
    # Limit document/file sampling
    sample_size = params.get('sample_size', 20)
    
    # For cloud storage
    max_buckets = params.get('max_buckets', 10)
    max_files = params.get('max_files', 50)
```

#### 4. Use Estimated (Not Exact) Counts

| Data Source | Fast Estimate | Slow Exact |
|-------------|---------------|------------|
| MySQL | `TABLE_ROWS` (instant) | `COUNT(*)` (seconds) |
| PostgreSQL | `n_live_tup` (instant) | `COUNT(*)` (seconds) |
| MongoDB | `estimated_document_count()` | `count_documents()` |
| S3 | File count | Read all files |

### Real-World Example: MySQL Optimization

**BEFORE** (35 seconds for 77 tables):
```python
for table_name in table_names:
    cursor.execute(f"DESCRIBE {table_name}")  # Query #1
    cursor.execute(f"SELECT COUNT(*) FROM {table_name}")  # Query #2 (SLOW!)
```

**AFTER** (< 1 second for 77 tables):
```python
# Query 1: Get all tables with estimated row counts
cursor.execute("""
    SELECT TABLE_NAME, TABLE_ROWS 
    FROM INFORMATION_SCHEMA.TABLES
    WHERE TABLE_SCHEMA = %s
""", (database,))
row_count_map = {row[0]: row[1] for row in cursor.fetchall()}

# Query 2: Get ALL columns for ALL tables
cursor.execute("""
    SELECT TABLE_NAME, COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE
    FROM INFORMATION_SCHEMA.COLUMNS
    WHERE TABLE_SCHEMA = %s
    ORDER BY TABLE_NAME, ORDINAL_POSITION
""", (database,))

# Group in memory (fast!)
columns_by_table = {}
for col in cursor.fetchall():
    columns_by_table[col[0]].append({...})
```

**Result**: 35x faster! ⚡

### Optimization Patterns by Connector Type

| Connector Type | Key Strategy | Expected Time |
|----------------|--------------|---------------|
| **Relational DB** | Use INFORMATION_SCHEMA, batch all queries | < 1 sec |
| **NoSQL** | Use estimated counts, sample 20 docs | < 2 sec |
| **Cloud Storage** | Limit bucket/file scans, parallel requests | < 3 sec |
| **API/SaaS** | Cache schema, use metadata endpoints | < 2 sec |
| **Data Warehouse** | Use system tables, avoid full scans | < 2 sec |

## Common Patterns

### Pattern 1: Database Connector
```python
class DatabaseMCPServer(BaseMCPConnector):
    def discover_schema(self, params):
        conn = self._get_connection(params['config'])
        tables = self._list_tables(conn)
        return {
            "success": True,
            "tables": [
                {
                    "name": table,
                    "columns": self._get_columns(conn, table),
                    "row_count": self._count_rows(conn, table)
                }
                for table in tables
            ]
        }
```

### Pattern 2: Cloud Storage Connector
```python
class S3MCPServer(BaseMCPConnector):
    def discover_schema(self, params):
        buckets = self._list_buckets(params['config'])
        return {
            "success": True,
            "tables": [
                {
                    "name": bucket,
                    "columns": self._infer_schema_from_parquet(bucket),
                    "row_count": self._count_objects(bucket)
                }
                for bucket in buckets
            ]
        }
```

### Pattern 3: API Connector
```python
class SalesforceMCPServer(BaseMCPConnector):
    def discover_schema(self, params):
        client = self._get_client(params['config'])
        objects = client.list_objects()
        return {
            "success": True,
            "tables": [
                {
                    "name": obj['name'],
                    "columns": obj['fields'],
                    "row_count": client.count_records(obj['name'])
                }
                for obj in objects
            ]
        }
```

## Testing Checklist

- [ ] `test_connection()` works with valid credentials
- [ ] `test_connection()` fails gracefully with invalid credentials
- [ ] `discover_schema()` returns all tables
- [ ] `discover_schema()` returns correct column types
- [ ] `discover_schema()` handles empty databases
- [ ] `validate_config()` catches missing required fields
- [ ] `export()` handles pagination correctly
- [ ] `export()` serializes all data types properly
- [ ] `import()` creates tables if needed (optional)
- [ ] Connector passes validation: `python scripts/mcp-connectors/validate_connector.py <name>`

## Troubleshooting

### "Method not found: discover_schema"
→ Make sure method is implemented and registered in `handle_request()`

### "Tables not showing in UI"
→ Check `discover_schema()` returns correct format:
```json
{"success": true, "tables": [...], "total_tables": N}
```

### "Connection test passes but schema discovery fails"
→ User might not have permissions to list tables. Check grants.

### "Type errors when exporting data"
→ Serialize dates, decimals, bytes to JSON-compatible types
