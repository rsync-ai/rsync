# Dynamic MCP Connector Optimization Strategy
## How Dynamically Generated Connectors Achieve Optimal Schema Discovery

> **Status: design strategy, not a description of shipped behaviour.**
> Layer 2 is real — connectors are generated by an agentic pipeline.
> Layers 1, 3 and 4 are **not wired up**. `base_connector.py` carries the scaffolding —
> `OPTIMIZATION_TEMPLATES` (`shared/mcp-connectors/base_connector.py:879`), `_apply_limits`,
> `_get_optimization_tips`, `_check_anti_patterns`, `_measure_performance` — but it is inert:
> the `optimization_templates.json` it loads is not in the repo, so the dict is always empty;
> `self.optimization_category` is initialised to `None` (`:1004`) and never assigned anywhere;
> and the helpers have no callers outside the `discover_schema` docstring (`:1605-1611`).
> `get_capabilities()` therefore reports `optimization_category: null` and a
> `performance_target_ms` nothing measures against (`:1772-1773`).
> Tracked as `KI-CONNECTOR-OPTIMIZATION-LAYER-IS-INERT`.

## Problem Statement
When AI agents dynamically generate new MCP connectors, how do they ensure optimal schema discovery performance (< 2 seconds for 100+ tables)?

**Challenge**: Can't rely on manual optimization for every new connector type.

## Layer 1: Category-Based Optimization Templates

### Core Concept
Every data source category has **proven optimization patterns** that work universally.

### Categories & Optimization Templates

#### 1️⃣ **Relational Databases** (MySQL, PostgreSQL, SQL Server, Oracle)

**Optimization Pattern**:
```python
TEMPLATE = {
    "optimization_strategy": "metadata_catalog_batch",
    "key_principles": [
        "Use INFORMATION_SCHEMA (never SHOW/DESCRIBE per table)",
        "Batch all table queries into ONE query",
        "Batch all column queries into ONE query",
        "Use estimated row counts (TABLE_ROWS, pg_stat_user_tables)",
        "Never use COUNT(*) per table"
    ],
    "queries": {
        "tables_with_counts": "SELECT table_name, table_rows FROM information_schema.tables WHERE table_schema = ?",
        "all_columns": "SELECT table_name, column_name, data_type, is_nullable FROM information_schema.columns WHERE table_schema = ? ORDER BY table_name, ordinal_position"
    },
    "expected_time": "< 1 second for 100 tables"
}
```

## Layer 3: Runtime Performance Validation

### Automatic Performance Profiling

Every connector execution is profiled:

```python
class MCPExecutor:
    def discover_schema(self, connector_type, config):
        start_time = time.time()
        
        # Execute discovery
        result = connector.discover_schema(config)
        
        execution_time = time.time() - start_time
        
        # Log performance metrics
        telemetry.log_metric({
            "connector": connector_type,
            "operation": "discover_schema",
            "execution_time_ms": execution_time * 1000,
            "table_count": len(result.get("tables", [])),
            "status": "success" if result["success"] else "failed"
        })
        
        # Alert if slow
        if execution_time > 2.0:
            alert_optimization_needed(connector_type, execution_time)
        
        return result
```

## Layer 4: Self-Improvement Feedback Loop

### Learning from Performance Data

```python
class OptimizationLearner:
    def analyze_performance_patterns(self):
        # Analyze all connector executions
        slow_connectors = query_telemetry("""
            SELECT 
                connector_type,
                AVG(execution_time_ms) as avg_time,
                MAX(execution_time_ms) as max_time,
                COUNT(*) as executions
            FROM connector_performance
            WHERE operation = 'discover_schema'
            GROUP BY connector_type
            HAVING avg_time > 2000
        """)
        
        for connector in slow_connectors:
            # Generate optimization suggestions
            suggestions = self.analyze_connector_code(connector["connector_type"])
            
            # Automatically apply optimizations
            if suggestions["confidence"] > 0.9:
                self.auto_optimize(connector["connector_type"], suggestions)
            else:
                self.create_human_review_task(connector, suggestions)
```

## Proposed implementation: intelligent connector generator

> **Sketch, not shipped.** There is no `intelligent_generator.py` in this repo, and none of
> `IntelligentConnectorGenerator`, `OptimizationTemplate`, `OptimizationLearner` or
> `query_telemetry` appears in any Python file. Connector generation is a separate
> pipeline entirely.
> The code below is illustrative.

```python
#!/usr/bin/env python3
"""
Intelligent MCP Connector Generator
Automatically generates optimized connectors using multi-layered approach.
"""

import json
from typing import Dict, List
from dataclasses import dataclass

@dataclass
class OptimizationTemplate:
    category: str
    strategy: str
    principles: List[str]
    queries: Dict[str, str]
    parameters: Dict[str, any]
    expected_time: str

# Layer 1: Optimization Templates
OPTIMIZATION_TEMPLATES = {
    "relational_db": OptimizationTemplate(
        category="relational_db",
        strategy="metadata_catalog_batch",
        principles=[
            "Use INFORMATION_SCHEMA for all metadata",
            "Batch table and column queries",
            "Use estimated row counts",
            "Never use COUNT(*) per table"
        ],
        queries={
            "tables": "SELECT table_name, table_rows FROM information_schema.tables WHERE table_schema = ?",
            "columns": "SELECT table_name, column_name, data_type FROM information_schema.columns WHERE table_schema = ?"
        },
        parameters={"max_tables": 100},
        expected_time="< 1 second"
    ),
    # ... other templates
}

class IntelligentConnectorGenerator:
    def __init__(self, llm_client):
        self.llm = llm_client
        self.templates = OPTIMIZATION_TEMPLATES
    
    def generate(self, data_source_name: str, data_source_info: Dict) -> str:
        """Generate optimized connector using multi-layered approach"""
        
        # Layer 1: Classify and get template
        category = self.classify_data_source(data_source_info)
        template = self.templates[category]
        
        # Layer 2: LLM generates code with template constraints
        prompt = self._build_optimization_prompt(
            data_source_name, 
            data_source_info, 
            template
        )
        
        code = self.llm.generate_code(prompt)
        
        # Layer 3: Validate optimization patterns
        validation = self.validate_code(code, template)
        
        if not validation["passed"]:
            # Retry with fixes
            code = self.fix_optimization_issues(code, validation["issues"])
        
        return code
    
    def classify_data_source(self, info: Dict) -> str:
        """Classify data source into optimization category"""
        keywords = {
            "relational_db": ["mysql", "postgres", "sql server", "oracle", "mariadb"],
            "document_db": ["mongo", "couch", "dynamo"],
            "cloud_storage": ["s3", "gcs", "azure blob", "minio"],
            "data_warehouse": ["snowflake", "bigquery", "redshift"],
            "api_saas": ["salesforce", "hubspot", "stripe", "api"]
        }
        
        name_lower = info.get("name", "").lower()
        for category, terms in keywords.items():
            if any(term in name_lower for term in terms):
                return category
        
        # Use LLM to classify if unclear
        return self.llm_classify(info)
    
    def _build_optimization_prompt(self, name, info, template):
        return f"""Generate an optimized MCP connector for {name}.

DATA SOURCE INFO:
{json.dumps(info, indent=2)}

OPTIMIZATION CATEGORY: {template.category}
STRATEGY: {template.strategy}

CRITICAL REQUIREMENTS:
{chr(10).join(f'- {p}' for p in template.principles)}

TARGET PERFORMANCE: {template.expected_time}

OPTIMIZATION TEMPLATE QUERIES:
{json.dumps(template.queries, indent=2)}

REFERENCE IMPLEMENTATION (MySQL optimized):
```python
def discover_schema(self, params):
    database = config.get('database')
    
    # Query 1: All tables with estimated counts
    cursor.execute(\"\"\"
        SELECT TABLE_NAME, TABLE_ROWS 
        FROM INFORMATION_SCHEMA.TABLES
        WHERE TABLE_SCHEMA = %s
    \"\"\", (database,))
    
    # Query 2: ALL columns for ALL tables
    cursor.execute(\"\"\"
        SELECT TABLE_NAME, COLUMN_NAME, COLUMN_TYPE
        FROM INFORMATION_SCHEMA.COLUMNS
        WHERE TABLE_SCHEMA = %s
    \"\"\", (database,))
    
    # Group in memory (fast!)
    return {{"success": True, "tables": [...]}}
```

Generate the complete connector following these patterns EXACTLY.
Include performance logging.
"""
    
    def validate_code(self, code: str, template: OptimizationTemplate) -> Dict:
        """Validate that generated code follows optimization patterns"""
        issues = []
        
        # Check for anti-patterns
        if "for " in code and "COUNT(*)" in code:
            issues.append({
                "severity": "HIGH",
                "message": "Using COUNT(*) in loop - will be slow!",
                "fix": "Use estimated row counts from metadata catalog"
            })
        
        if code.count("cursor.execute") > 3:
            issues.append({
                "severity": "MEDIUM",
                "message": f"Too many queries ({code.count('cursor.execute')})",
                "fix": "Batch queries - target is 2 queries max"
            })
        
        # Check for required patterns
        if template.category == "relational_db":
            if "INFORMATION_SCHEMA" not in code.upper():
                issues.append({
                    "severity": "HIGH",
                    "message": "Not using INFORMATION_SCHEMA",
                    "fix": "Use INFORMATION_SCHEMA for metadata"
                })
        
        return {
            "passed": len(issues) == 0,
            "issues": issues
        }
```

## Summary: Best Approach

### ✅ **Hybrid Multi-Layered Strategy**

**Why this works better than "LLM only" or "Template only":**

1. **Templates provide proven patterns** - Fast baseline, no guesswork
2. **LLMs adapt to new sources** - Flexibility for unknown types
3. **Runtime validation catches issues** - Safety net
4. **Feedback loop improves system** - Gets better over time

### Key Success Factors

| Factor | Implementation |
|--------|----------------|
| **Consistency** | Category-based templates ensure all DBs use INFORMATION_SCHEMA |
| **Flexibility** | LLMs can adapt templates to specific data source quirks |
| **Safety** | Runtime profiling catches slow connectors automatically |
| **Evolution** | System learns from every execution and improves |

### Performance Guarantee

```python
# Every generated connector MUST pass:
assert execution_time < 2.0, "Schema discovery too slow"
assert queries_executed <= 3, "Too many queries"
assert uses_metadata_catalog == True, "Must use metadata"
```

## Conclusion

**Answer**: The best way is **NOT** "LLM only" or "Template only" - it's a **4-layer hybrid system**:

1. 🏗️ **Templates** = Proven optimization patterns per category
2. 🧠 **LLM** = Adapts templates to specific data sources
3. ⚡ **Runtime** = Validates performance in production
4. 🔄 **Feedback** = Continuously improves from data

This ensures **every dynamically generated connector** is optimized from day 1, and gets better over time!
