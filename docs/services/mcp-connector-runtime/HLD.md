## MCP Connector Runtime — HLD

### Purpose
MCP connectors are the **execution plugins** of rsync-ai. Each connector runs as its own **MCP server** (container) and exposes tools like:
- `test_connection`
- `discover_schema`
- `export` / `import` (and connector-specific actions)

Connectors are:
- stored on disk under `shared/mcp-connectors/<id>/versions/<version>/...`
- deployed as versioned containers named:
  - `rsync-ai-<id>-vX-Y-Z-mcp`

### Runtime Interface
- Most connectors run in **HTTP MCP mode**:
  - `GET /health`
  - JSON-RPC style tool execution endpoint (connector runtime contract)
- Container port: `8000` (default inside container)

### Responsibilities
- Implement connector-specific auth + IO logic using shared base libraries (where applicable).
- Provide consistent tool contracts required by the orchestrator and executor.

### Deployment Model
- `docker-compose.mcp.yml` is auto-generated by `scripts/mcp_generate_compose.py`
- The tool-generator can also build/start connector containers directly (best-effort) using the docker socket.

### Dependencies
- Target systems (DB/API/S3/etc.) depending on connector.
- Shared artifact volume is mounted into containers at build/run time (depending on strategy).
